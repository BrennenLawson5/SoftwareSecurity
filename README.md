# SoftwareSecurity

Artemis Financial is a financial consulting firm that develops customized investment plans for their clients, and their primary concern was making sure that all sensitive financial data transmitted through its web application was secure. The issue they wanted me to address involved choosing the right algorithm cipher, making sure that data transmission was secure, and identifying and remediating software vulnerabilities. 

One thing I did well regarding vulnerabilities was being able to research certain vulnerabilities that were outdated and find the solution for them. In the code bases we were given, there were a lot of things that needed to be upgraded that would make the current vulnerabilities obsolete, but we were not asked to do that. Coding securely is crucial because even the smallest vulnerability could possibly lead to large-scale breaches, financial loss, or breaking the user's trust. The value of software security is very great, because without it, you put everything within the company at risk. Everything today has software implemented into it so without proper security, anything can be exploited. 

I would say that the most challenging part of the vulnerability assessment was identifying false positives, because you have to understand which dependencies actually pose a security risk. I had to research CVE reports and determine which vulnerabilities applied to Artemis Financial's specific version of the dependency. But, doing this helped to deepen my understanding of secure coding practices and dependency management. 

To increase layers of security, I implemented HTTPS encryption by configuring a self-signed SSL certificate through Spring Boot's application properties. This made sure that all client-server communication was encrypted. In future projects, I plan to use tools like OWASP ZAP or SonarQube for dynamic and static analysis to identify additional vulnerabilities. 

After refactoring the app and updating dependencies, I re-ran the dependency-check and tested the web service endpoints to make sure that the functionality remained intact. Also, I reviewed the Maven build output and confirmed that the HTTPS configuration was still active. I was able to confirm that there were no new vulnerabilities introduced. 

The tools I used were OWASP Dependency-Check, Maven, Eclipse IDE, and the internet. One thing I did that helped was reviewing the OWASP top ten documentation to get a better understanding of common web security risks. There were many other resources available on the internet that helped me understand things better too. 

I think this assignment and other assignments in the course show my ability to identify, assess, and remediate security risks in real-world scenarios, but most importantly, it shows my ability to adapt and learn, as I have never done any software security stuff before taking this class. It also shows that I can use industry-standard tools and apply secure coding techniques and principles to maintain data integrity and confidentiality. Showing this to my future employers will serve as an example of my understanding of proper software design, risk mitigation, and code management, which are all critical skills in the world of cybersecurity and software.
